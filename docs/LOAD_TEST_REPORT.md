## 压测方法

`scripts/load-test.ts`：

1. 用 10 行 `WARM_` 文件预热上传路由（不计入指标）；
2. 连续 5 次上传 10,000 行文件，记录每次响应时间，计算 P95；
3. 轮询第一个任务至终态，计算从创建到完成的总耗时；
4. 校验成功/失败行数与 HTTP 5xx 数量；
5. 输出 JSON 报告。

## 数据库连接

连接池上限 10；单批峰值使用 1 个连接复用，实测阶段耗时无连接排队特征（`insert` P95 392ms）。Worker 并发 4 时峰值连接数约为 4~8。

## 结论与已知瓶颈

结论：10,000 行/分钟目标达成，上传 P95 387ms，全链路 3.3s，错误明细与监控数据完整。

已知瓶颈与优化方向：

- **文件解析（parse）** 是当前最大耗时项（P95 1221ms），因为每批按需读取文件前缀（10 批合计读取约 5,500 万单元格量级的 XML 流）。可改为“文件解析一次落中间态 + 分片消费”或提高 Worker 并发；
- **批量 UPSERT** 在大批量下可切换 `COPY` / 临时表合并进一步提升；
- 若吞吐提升到 50,000 行/分钟，优先扩展数据库写入能力（连接池、分库）与 Worker 实例数。
